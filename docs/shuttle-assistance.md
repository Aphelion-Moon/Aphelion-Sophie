# Shuttle assistance queue and resolution

Scope: P05, P06, P09, P14 and the Shuttle portion of P17; partial T04, T05, T07, T13–T16 and T53–T55 evidence. This adds a Staff queue and retained resolution actions to the existing Ask Staff flow. It uses the approved runtime and driver, with no new dependency, live command registration, service installation or production changes.

## Staff workflow

`/shuttle queue` returns an ephemeral page of up to five outstanding requests, oldest interaction ID first. Each entry contains a member reference, stored case state and channel reference where available. Resolve controls identify individual requests; Refresh starts again and Next page uses a bounded numeric cursor. The renderer accepts only this closed metadata shape. It has no conversation excerpts, guidance bodies, forms, attachments, notes, external URLs or AI path. All response mentions are suppressed.

Both Staff and lead ops can use the queue through the existing `case.manage` policy for Shuttle cases. Being the requester, supplying a role array, seeing a channel or holding Discord Administrator is insufficient. Current Muzzled or timed-out staff cannot use these operations. The verifier binds every request to the configured application/guild and verified member. Each store operation reauthorizes, and queue delivery resolves the actor and reads the queue again after command execution, so permission loss before the response suppresses its metadata.

Only records bound to the Shuttle case type enter this queue. It is not a general ticket list, and it cannot surface Head Admin contact records. Channel references describe retained routing metadata; they do not certify current Discord permission overwrites or grant channel access. Opening a reference uses Discord's own permissions. Member entry navigation and static screen delivery retain their separate exact audience checks. This queue does not fetch channel messages or preview a case.

The presentation uses the existing legacy embeds and Action Rows: at most five Resolve buttons in one row and two navigation buttons in another. API contracts checked on 19 September 2026: [legacy components](https://docs.discord.com/developers/components/reference#legacy-message-component-behavior), [buttons](https://docs.discord.com/developers/components/reference#button) and [subcommands](https://docs.discord.com/developers/interactions/application-commands#subcommands-and-subcommand-groups). Compatibility and visual/accessibility checks in Discord remain open.

## Retained resolution

Ask Staff coalesces repeated clicks while that session has an open request. Resolving it retains the original request, changes its status/revision and appends a record containing the verified staff grant, interaction identity and time. A member can ask again from the current Shuttle screen; this creates a new request while keeping the resolved history. Outstanding requests remain visible until a human resolves them, including after completion, closure, withdrawal or departure. There is no expiry or inferred claim that the conversation has ended.

`describeShuttleHelp` obtains the actual request owner for a fresh membership observation. `resolveShuttleHelp` locks that member, the bound session/case and the request in the shared lock order. It checks current Staff authority, immutable case policy and expected request revision. The resolution, audit record, deduplication receipt and any required screen replacement commit together. A final authority check prevents permission loss during the transaction from committing the action. Failed audit/screen writes roll everything back; the usual member-operation savepoint still preserves valid observed revocations after domain denial.

Duplicate interactions report the retained outcome without a second audit event. Different interactions using an already resolved revision are stale. A serialized actor or a mismatched member observation cannot resolve the request. Resolving an older run does not replace the current screen of a newer repeat or resolve its separate request.

An eligible current screen is refreshed without the outstanding-help banner. If its pinned publication pauses on help, the action also records [Staff resumption](shuttle-pause.md), rotating the session version and controls without advancing a page. A still-valid paused run cannot be resumed while Muzzled or durably muted; the request stays open. Historical requests can be resolved without restoring their session. Resolution itself does not clear Muzzled, grant Whitelist, reopen a case or publish withdrawn guidance.

## Migration and evidence

Migration `010-shuttle-assistance.sql` adds open/resolved status, bounded revisions, one-open-request-per-session uniqueness, a numeric queue index and retained resolution records. Existing duplicate open requests cause migration failure rather than being deleted or silently merged. Earlier migrations are unchanged. The test core identity has no DELETE or migration privilege; the knowledge identity cannot read these tables.

Three contract tests exercise signed routing, bounded metadata/pagination and the explicit command union. H01–H13 exercise PostgreSQL, real authorization/signatures and simulated Discord: request/resolve/re-request, current Staff checks, concurrent duplicates, audit/outbox failure, mid-operation revocation, response-time revocation, pagination, older repeats, Muzzled members, historical requests, forged identities, case-type separation, policy/gate changes and actual loopback HTTP delivery. S17 restarts the isolated database and checks the retained request, staff audit and recovered screen. No real case or onboarding-session content is used.

Published `helpPauses: false` permits continued progression; `true` now supports a durable pause and logged resumption. Paused entries use a Resolve / resume control; closing a historical request does not imply eligibility to resume. W01–W12 exercise this rule, pending/late grants and private responses. New requests now commit separate [Staff alerts](shuttle-alerts.md); the queue itself does not certify their delivery or human attention. Assignment, delivery-issue review/repair, the editor/dashboard, full case lifecycle and production composition remain open.
