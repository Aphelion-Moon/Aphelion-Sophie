# ADR 0003 — Driver and local database test scope

Status: recorded implementation scope decision, 18 September 2026, within the owner's approved PostgreSQL work. This is not operator approval for a production distribution or a blanket licence exception.

Select the directly reused **pg 8.23.0** project under MIT. Use its JavaScript driver and built-in pool, with our own small versioned SQL migrations and outbox. Do not install pg-native, an ORM, a migration framework or a separate queue system. Exact transitive versions, npm SHA-512 integrity, archive SHA-256 and licence notices are inventoried in `legal/storage-packages.json`. Install scripts are disabled.

The owner's direct-project MIT requirement does not imply that indirect components are MIT. Explicitly include **pg-int8 1.0.1** and **split2 4.2.0**, both ISC, only as indirect components of this approved database integration. Keep their original notices. The other resolved packages are MIT. The optional MIT pg-cloudflare package is reviewed because it occurs in the lockfile, but is omitted from installation on this Windows runtime. The driver does not enable Cloudflare or a cloud service. Postgres.js 3.4.9 was evaluated and not adopted (Unlicense, not MIT).

For synthetic integration tests only, use the already installed PostgreSQL **17.11** server/client binaries read-only, with hashes recorded before use. Run a new cluster under the ignored workspace `.local` directory, listening on IPv4 loopback on a newly selected port, with SCRAM passwords generated for this run. Stop it at test completion; do not register a service, change firewall rules or connect to an existing database. The installed server's PostgreSQL notice and command-line bundle notices are separately hashed and reviewed. This local use includes the shipped supporting libraries under their own terms (including ICU/Unicode, OpenSSL/Apache, zlib, BSD, MIT and LGPL components); it neither copies them into the repository nor relicenses or approves redistribution of them. pgAdmin, StackBuilder and their dependencies are outside this test scope.

Production packaging remains a separate gate: review the exact server and Node distribution, all redistributed DLLs and their source/notice obligations, service identities, ACLs and recovery plan. Never claim that passing these tests approves that distribution. Existing game services, data and credentials are outside scope.

Transactions follow the [node-postgres transaction contract](https://node-postgres.com/features/transactions): one checked-out connection for every statement until commit/rollback. Queue claims use PostgreSQL row locks and `SKIP LOCKED`; fencing protects database commits, not an already in-flight Discord request. No live Discord dispatcher is enabled by this decision.
