# Local project constraints

This is an explicitly invoked development tool for approved web interfaces. It does
not add runtime AI features or authorize unrelated application changes.

- Meridian website: preserve the approved cassette-futurist, worn-station design and
  its intentional contrast with newer development. Do not normalize it into a generic
  minimal software-product site.
- Sophie dashboard: preserve the neon protogen identity and intentional cyan/teal and
  magenta accents. Do not impose a single accent or mandatory desaturation. Follow the
  repository owner decisions and existing brand profile; preserve approved source artwork.
- Wagtail wiki: inspect and use the actual Wagtail/Django implementation and existing
  design conventions. A missing stack dataset is not permission to add React, Next.js,
  or Tailwind. A MediaWiki installation is not proof of a Wagtail development checkout.

For Sophie, keep AI assistance out of support tickets, player reports, staff-created
tickets, and The Shuttle onboarding workflows. No model may see their messages, forms,
attachments, transcripts, staff notes, or onboarding-session content. Do not query,
preview, summarize, classify, draft from, or smoke-test with real ticket data. Do not
send synthetic ticket sentinels to AI either. Use neutral UI-only queries such as
`keyboard focus modal`. Static branding does not authorize an AI ticket data path.

Read the relevant project's current instructions and design decisions. Use the smallest
relevant query. Treat catalog values as suggestions subordinate to those decisions;
they neither mandate a new design system nor authorize a dependency installation.
Preserve approved design systems. Never overwrite them or use `--force` without
explicit authorization. Persist only when requested and to an explicit project path.
